## Endpoints and paired analysis

Report separately for each suite; do not pool the three suites into a misleading benchmark average.

**Primary:** lane-minus-plain accuracy, averaging both generation seeds per task, denominator all scheduled task×seed responses. Report arm solved counts, paired losses/gains, per-seed counts and censor/error rates. Primary uncertainty: **20,000 paired task-cluster bootstrap draws**, RNG20261104, sorted task IDs sampled with replacement at the suite's n; retain **both seeds unchanged** and both arms together for every selected task. No seed resampling or independent-sample test on2n rows. Percentile CI endpoints500/19,499.

For a formal paired accuracy test, let `d_i` be lane correct count minus plain correct count across the two seeds (−2..2). Use an **exact task-cluster sign-flip test**, flipping both seeds' arm labels together per independent task. Compute the distribution of `sum(±abs(d_i))` by integer dynamic programming, ignoring zero weights; two-sided p is probability of absolute sum≥the observed absolute sum, including ties. All ties gives p=1. This relies on task-level arm exchangeability under the null; it is not an inference that seeds are independent or tasks random samples of all programming. Apply **Holm across the three suite accuracy tests** at familywise.05. Row-level McNemar and seed101-only McNemar may be descriptive checks, **not substitutes for the registered two-seed task-cluster test**. A tied bootstrap is not evidence of population non-inferiority. Do not infer non-inferiority from nonsignificance.

**Secondary tokens:** all chronological returned native IDs, including tool/protocol/forced output once, prompt excluded. Hash/reconcile IDs, completion and inserted-result totals; retain reasoning/content and prompt counts separately. Completion usage alone is insufficient. Missing IDs/usage is missing evidence, never zero or characters/4; report coverage, observed lower bounds and explicitly selected paired-complete sensitivities, withholding the full-cohort token claim if accounting is incomplete.

**Secondary time:** client monotonic end-to-end wall including prefill, every tool round and final delivery, plus server timing/tool execution separately. Include failed/deadline elapsed time. For tokens/time report mean/median, paired sums ratio and paired mean difference, CI95 from the same bootstrap draws. Report complete-both sensitivities and both net/positive savings contributions from pairs censored in either arm. No uncensored speedup claim if >25% of savings comes from censored pairs. Token/time intervals are descriptive; do not select the favorable metric or suite as a confirmatory global result. Published token/time baselines are unavailable, not zero.

This is estimation, not a powered pass/fail retention trial. A **favorable local efficiency result** requires no net solve decrease, complete safety/accounting, token and time point ratios<1 with both CI uppers<1, no censoring reversal and ≤25% net/positive censor contribution. Report every isolated solve loss even then; this is not population non-inferiority. Otherwise report mixed/inconclusive/regression according to the observed endpoints, not a blanket win. Accuracy significance uses only the Holm-adjusted primary tests.
