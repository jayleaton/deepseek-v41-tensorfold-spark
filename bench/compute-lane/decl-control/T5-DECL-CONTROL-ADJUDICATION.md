## Allowed public wording and relation to prior experiments

“On fixed subsets of48 GSM8K,20 MATH-500 and24 original HumanEval tasks with two seeds, the served2.80bpw DeepSeek-V4.1-Flash-1017 model produced exactly the same native outputs with the Python declaration whether execution was enabled or disabled. No dataset reply called Python. Adding the declaration with execution disabled reproduced the previously observed23.7%,21.9% and27.4% reductions in returned tokens versus no declaration. Enabling execution added no detected benefit on this cohort. Prompt-plus-output totals increased; GSM strict-format accuracy fell slightly and HumanEval cost savings were dominated by one capped response.” Attach intervals and the secondary-grade/censor qualifications when presenting individual suite results.

Thus **execution is unnecessary for these observed output differences**. It is reasonable to call this an effect of adding the tool declaration in this controlled configuration. It does not identify a semantic belief/trust mechanism separately from declaration length/content, establish direct served-array identity, prove the lane never helps, or show a general accuracy-preserving speedup. These are short, already observed public subsets, not full benchmark scores or upstream unquantized scores. Historical BASE reference rows remain historical only.

This neither contradicts nor repairs **W9/AB3**. W9 compared trace on/off with the bounded runner already present in both arms: its −11.24% token estimate failed promotion on solves, safety/censoring and other gates. AB3's call-heavy tool configurations had authenticated actual executions; full versus lane was −13.17% with CI[−26.08%,+0.98%] and retained the newline-placement safety failure. Those interventions/cohorts differ, and neither supplied this matched declared-but-disabled control. Their large descriptive differences versus plain cannot now be assigned entirely to either execution or declaration. Conversely, actual correct computations in those receipts do not demonstrate execution benefit on standard-suite replies that never called anything. The present result motivates separating prompt/declaration effects from execution effects in future call-using studies; it changes neither prior frozen verdict.

## Recommendation

A further test is useful **only as a prospectively frozen computation-demanding D/L study**, not another replay of these no-call subsets: choose120 new independent, ordinary-looking task specifications (for example, a fixed mix of integer/modular arithmetic, exact division, small DP and graph/aggregation problems), verify answers independently, use two seeds and identical declarations, and retain all **480 replies**. Do not instruct only L to use Python, select tasks from measured call rates, or analyze only call-using replies. Pre-register an activation adequacy threshold (for example, at least30 distinct L tasks execute) and treat failure as insufficient execution exposure, without excluding results. Under planning assumptions of20% task-level solve discordance and maximal within-task seed correlation,120 tasks target only roughly11–12pp solve effects at80% power; a paired log-token SD0.5 similarly suggests about12% effects, **not a guarantee derived from this zero-effect cohort**. Two balanced D/L turns require four cold boots; at an assumed10–20s per reply, generation is1.3–2.7GPU hours plus boot/restore/qualification overhead, so budget **about3–5GPU hours**, with a frozen wall budget and incomplete-study rule. The270s cap allows a36-request-hour extreme before overhead, so that planning range is not a promised upper bound. Freeze this follow-up separately before any new outcomes; none is launched here.
